## 1. Общий конвейер: кто и когда тикает

**Кадр армии** — `GameManager._physics_process_timed` (:536-755):
1. `army.rebuild_grid()` — плоская сетка соседей в C# целиком;
2. `_sweep_corridors` / `_sweep_melee` / `_sweep_volleys` (раз в 3 тика) /
   радары отрядов;
3. **дрёма перезарядки** `army.tick_snooze` → проснувшиеся парами
   `[строка, остаток]` → `_atk_wake`;
4. **список строк от ядра** `army.tick_rows(...)` (`ArmyCore.cs:4997-5079`) —
   ядро само решает, кому ВООБЩЕ нужен GDScript-тик в этом кадре: строка
   пропускается, если её ведёт матрица/напор/автопилот/дрёма в ATTACKING,
   если это полутакт контакта (каждый второй личный тик), если она в
   `FIdleWait` (ядро само убавляет таймер агро), или если она скрыта туманом
   (тогда — раз в `fog_slow_div` = 6 тиков). `FTickAlways` (лучник, монах,
   рабочий, гнолл, тролль, туша, всадник без командира) — всегда в GDScript;
5. `_flush_poses` → `rear_press_pass` → `autopilot_pass` → `batch_move_queued`
   → `batch_separation` → `_physics_tail` (смыкание, мораль).

**Автомат бойца** `Unit.tick_physics` (:4743-5010): `State {IDLE, MOVING,
ATTACKING, GATHERING, RETURNING, DEAD, BUILDING}`. IDLE → таймер агро
(`AGGRO_INTERVAL_CALM` 2.0 с, после находки `HOT` 0.5 с) → `_check_auto_aggro`
(:8276-8420) → при `core_tick_list` взводит ожидание в ядре `idle_wait_arm`
и до истечения таймера в GDScript не входит вовсе.

**Порядок выбора цели** (`_check_auto_aggro`):
1. замок игрока (`_lock_next_victim`; пока цель в `_lock_sight_range()` —
   стрелку `max(range×3, 60)`, пехоте `max(range×2, 10)` — другую не брать);
2. стойка «держать»: только лобовой сектор `PHALANX_FRONT_COS` 0.34 и в
   длине оружия;
3. `watch = max(AGGRO_RADIUS 5.0, attack_range)`, в бою отряда — не меньше
   `PULL_UP_RANGE` 7; стрелковый отряд читает радар, прочие —
   **кэш цели отряда** `squad_target_get` (TTL `squad_target_ttl` 0.4 с,
   скан делает знаменосец, боец берёт ближайшего из ТОГО ЖЕ чужого отряда);
4. поводок от знаменосца `AGGRO_LEASH` 14 м; за бегущими/отходящими не
   гнаться; стрелок с места не сходит.

Скан сетки — `SpatialGrid.best_enemy` → C# `BestEnemyPrio` (`ArmyCore.cs:
1999-2049`): счёт `dist + attackers × CROWD_PENALTY 2.5`, делённый на вес
цели (стрелок: `_tgtW`, конница: `_tgtWc`), потом GDScript добавляет здания
из снимка. `EnemyAt` (:2161) — только для стрел: ПЕРВЫЙ чужой в радиусе.

**Гибель цели**: сигнал `died` → `_on_attack_target_died` (:3060) обнуляет
цель, фаза `_retarget_timer = (row % 6) × 0.033`; затем `_process_attack`
раз в `RETARGET_RETRY_SEC` 0.2: замок → `squad_duel_target` (модель из
бухгалтерии `_sweep_melee`) → `_find_nearest_enemy_in_range(seek)`, где
`seek = max(range, FORCED_RETARGET_RANGE 6)` для приказа игрока, иначе
`attack_range` → нет цели: `_resume_march` / IDLE + `squad_close_ranks`.

**Приоритет вмешательств**: замок игрока → заслон телом (`blocker_pull` /
`blocker_march`, полоса `attack_range + INTERCEPT_MARGIN 0.8`, под замком
`min(range, LOCK_BLOCKER_RANGE 1.6) + 0.8`) → ответ на удар в упор
(`take_damage` :9185) → авто-агро. Сцепка `_melee_grip`: заслон по контакту
не бросается на границе дальности.

**Урон** (`Unit.take_damage` :9070-9175):
```
d = defense + armor + upgrade + bonus_armor + bonus_defense + vet + аура + стойка(+5)
d ×= PANIC_ARMOR_MULT 0.70 (паника); d ×= (1 − pen) (пробитие)
actual = max(amount × 0.15, amount × 25 / (25 + d))      # ARMOR_SOFTNESS 25
actual ×= щит/стена; ×= SPRINT_DAMAGE_MULT 1.35 бегущему
```

## 2. Копейщик (`scripts/Spearman.gd`)

Статы (`unit_stats_config.gd:28-41`): HP 180, ход 2.0 × 1.35 × 0.85, удар 14,
копьё 2.5 м, перезарядка 2.0 с (в обороне ×1.25 → 1.6 с), броня 3.

Цикл:
- **Покой** → таймер агро → в обороне обзор `FORMATION_AGGRO_RADIUS` 5.0,
  только сектор перед фронтом; ряд считается раз в `RANK_RECHECK` 0.25 с,
  брешь — раз в `PHALANX_ADVANCE_SCAN_MS` 200.
- **Обнаружение** — через кэш отряда (один скан на отряд за 0.4 с).
- **Сближение** — в атаке: до `reach + PULL_UP_MAX 14` подтягивание рядов на
  `PULL_UP_SPEED` 0.55 хода, дальше полный шаг с обходом (`_flank_step`,
  автопилот). В обороне поодиночке НЕ ходит: ходит стена целиком
  (`_wall_goal` сдвигает точку каждого на вектор сдвига центра —
  `_phalanx_march` :7144), одиночного подтягивания нет
  (`PHALANX_PULL_UP_SINGLE = false`).
- **Удар** — `_attack_timer ≤ 0` → `_effective_cooldown()`; касание
  откладывается на `MELEE_HIT_DELAY_MS` 150; потом **дрёма в ядре** до
  готовности (страж цели с люфтом 0.6 м).
- **Новая цель** — см. §1; в обороне цель не бросается, пока противник не
  ушёл из `_lock_sight_range`.
- **Лоб коннице** — `repels_charge() → true`, вес всадника в стене
  `CAV_WEIGHT_IN_WALL` 0.4; копьё опускается в «держать»/при разгоне на
  бойца (`_spear_leveled`, задержка до 300 мс).
- **Направленные листы** — 8 секторов по экранному углу с гистерезисом 15°;
  на ходу взгляд = курс отряда, только если расходится с ходом ≤ 60°.

## 3. Лучник (`scripts/Archer.gd`)

Статы: HP 110, ход 2.1, урон 22, дальность 15 (потолок `attack_range_cap`
25 — держится при рождении и при выдаче исследования), перезарядка 3.0 с
(делится на `ARCHER_DRILL[ур].fire` 0.85…1.25), стрела 20 м/с, дуга 0.20
дистанции.

- **Обнаружение — радар отряда** (`GameManager.gd:6061-6130`): один скан на
  отряд раз в `RADAR_INTERVAL_MS` 500 через знаменосца, радиус `range +
  RADAR_MARGIN 5`; на марше — дальний РЛС `MARCH_RADAR_SEC` 5.0.
- **Цель**: `pursues_target() → false`, `holds_ground_on_aggro() → true`;
  скан делит счёт на вес цели (туша ×2 — `BIG_TARGET_PRIO`);
  `_prefer_in_range` подменяет цель приказа на бойца того же отряда, до
  которого уже дострелить.
- **Удержание дистанции**: без приказа цель за дальностью бросается
  (:6537-6544); по приказу — подтягивание через `SQUAD_SHOT_SLACK` 6.0;
  первый дотянувшийся «объявляет» за отряд (`squad_ranged_engaged_set`) —
  остальные встают.
- **Баллистика** (`_on_attack_fired` :535-693, точку считает GDScript, полёт
  ведёт C#): старт +1.2 м, прицел `aim_height()` цели; упреждение двумя
  проходами `vel × travel × ARCHER_LEAD_FACTOR 1.0`, потолок 14 м; разброс
  `(0.35 + |v| × 0.20) × 1.7 × (1 − tighten) × drill.spread`; дуга
  `y = lerp + sin(πt) × dist × 0.20`, время полёта `dist / 20`.
  ⚠ Случайность берётся из глобального `randf()` (:653-675), а не из
  `AudioManager.rng` — правило CLAUDE.md о сеяном потоке здесь не
  соблюдено (так было и раньше).
- **Залп** (`_sweep_volleys`, раз в 3 тика): окно при готовности ≥ 0.7
  отряда либо через `VOLLEY_FORCE_MS` 2500; окно 200 мс, пауза 900; точка —
  центроид отряда-цели В МИГ ВЫСТРЕЛА; туча `clamp(spread, 1.10, 3.2)` по
  золотому углу (97 слотов).
- **Ближний бой при угрозе — ТАКОЙ ЛОГИКИ НЕТ.** Ни ближнего оружия, ни
  минимальной дистанции, ни отхода: удар в упор даёт общий ответ
  `command_attack(attacker)`, и лучник продолжает стрелять в упор теми же
  стрелами (22 урона, 3 с). На марше ответный рывок у лучника гасится
  (:9255). Это стоит знать владельцу: «лучники переключаются на мечи» —
  не существует.
- **Снайпер** (archer_2d/3d): `SNIPE_SQUAD_BASE` 3 снайпера, перепроверка
  0.5 с, очередь выстрелов `SNIPE_STAGGER_SEC` 0.14, заявка на цель 1.5 с,
  один выстрел — одна жизнь (`snipe_one_shot`).

## 6. Стрелы: почему не лагают

### Корень проблемы «у друга»

`instantiate()` + `add_child()` на каждую стрелу — это: разбор `PackedScene`,
создание объекта с его `_ready`, регистрация в дереве (`NOTIFICATION_ENTER_TREE`
по всей ветке, группы, сигналы), а у спрайта — ещё и свой вызов отрисовки.
`queue_free()` — отложенное удаление в конце кадра, то есть пик в самом
дорогом месте кадра; под .NET к этому добавляется управляемая обёртка, а
значит — сборщик мусора gen0/gen1, который в большом бою и даёт те самые
«фризы раз в несколько секунд». Сотня лучников × 3 с перезарядки = 30-40
созданий и удалений узлов в секунду, в залпе — 100 за один кадр. И каждый
узел-стрела со своим `_process` — это ещё и сотня вызовов GDScript в кадр.

### Как у нас: три слоя

**Слой 1 — ЗАПИСЬ ВМЕСТО УЗЛА (`projectile_core = true`).** На пути
выстрела узел Arrow НЕ создаётся вовсе: `GameManager.fire_projectile`
(:9392-9440) пишет запись в ядро `army.projectile_fire(...)`
(`ArmyCore.cs:4357-4374`) — старт, конец, высота дуги, темп, стрелок,
цель. Слот картинки берётся `RbAcquire` из free-list слоя; нет слота —
`lay.grow()` (удвоение от 64, потолка нет) и повтор. Этим путём стреляют
лучник, снайпер и гнолл (кость). На горячем пути — ни одного
`instantiate()`/`queue_free()`.

**Слой 2 — ПОЛЁТ И ПОПАДАНИЕ ОДНИМ C#-ПРОХОДОМ (`arrow_core`).**
`BatchArrows` (`ArmyCore.cs:4777-4851`) раз в кадр отрисовки по всем
полётам: `t += rate × dt`, `pos = lerp + sin(πt) × arc`, ось — производная,
запись 16 float в слот MultiMesh; попадание — `EnemyRowAt(x, z, HIT_RADIUS
0.35, fac)` по XZ (высота не проверяется — правило сохранено дословно со
времён узлов); попал — событие и swap-remove записи; долетел или вышел
`MAX_FLIGHT_SEC` 10.5 — `ProjectileLand` (втыкание с дрожанием
`STICK_JITTER` 0.21) и `MissNote` (звук промаха агрегируется по клеткам
32 м, до 8 групп). Измерено: 0.40 мс/кадр на 60-70 стрел в полёте.

**Слой 3 — ОДНА MultiMesh НА ВСЕ СТРЕЛЫ (`ArrowRenderer`).** Один
`MultiMeshInstance3D` с `use_colors`, шейдер `mm_arrow.gdshader`: ось и
дизер-растворение едут в instance-цвете; буфер и free-list слотов живут в
ядре (`RbAcquire/RbRelease/RbGrow`, `ArmyCore.cs:5428-5451`),
`RbRelease` обнуляет базис слота (экземпляр невидим). 36 торчащих стрел =
+1 вызов отрисовки, а не +36.

**События — один забор на кадр, урон сложен на жертву.**
`_dispatch_projectile_events` → `take_projectile_events_i/f`
(`PackedInt64Array`/`PackedFloat32Array`, шаг 8) → `_pj_consume`
(`GameManager.gd:9487-9600`): попадания складываются по строке жертвы, и на
жертву за кадр идёт ОДИН `take_damage(сумма)` — сумма до брони равна сумме
после, потому что броня долевая и линейная. Снайпер убивает с одного
попадания; одна стрела остаётся в теле (`projectile_stick`), прочие слоты
освобождаются; звук — один на группу 32 м. Мелочь: убийство засчитывается
только первому стрелку пачки.

**Торчащие стрелы** — тоже записи: `StuckTick` раз в кадр, срок
`STUCK_LIFETIME` 45 с + растворение 4 с (кость 5 / 1.5), потолок
`MAX_STUCK_ARROWS` 160 с вытеснением за 0.6 с; в трупах — пока не
вытеснят. ⚠ Расхождение: комментарий GDScript (:9752) говорит, что против
потолка считаются только негаснущие, а C# `StuckAdd` (:4546) считает всех,
включая гаснущих — лавины нет, но живых торчащих временно бывает > 160.

### Про «пул на 2000 стрел» — честно

Числа 2000 в коде **нет**. Пул УЗЛОВ Arrow существует только для старого
пути (`projectile_core = false`): `ARROW_POOL_MAX = 3000`
(`GameManager.gd:9247`, рассчитан под 2000 лучников × ~500 стрел в воздухе
+ 160 торчащих), **ленивый** (без предсоздания), это **стек** (LIFO
free-list: `spawn_arrow` делает `pop_back()`, `recycle_arrow` —
`append`, при переполнении `queue_free`), а не кольцевой буфер.
Активация `Arrow.launch()` (`Arrow.gd:224-256`) сбрасывает `_progress`,
`_life`, `_stuck_life`, `_in_corpse`, `_fading`, `_hit_node`, `_spent`,
`_pooled`, ставит `visible = true` и пишет слот; деактивация `_despawn()`
(:260-282) — `visible = false`, отмена полёта в ядре, `hide(slot)`,
`set_process(false)`, узел ОСТАЁТСЯ в дереве (без `remove_child`), слот
MultiMesh держится пожизненно и отдаётся в `NOTIFICATION_PREDELETE`.
Но при действующих ручках этот пул — запасная дорога: единственный
оставшийся `spawn_arrow` (`RoofGarrison.gd:606`, стрела в теле упавшего с
крыши) срабатывает только при выключенном ядре снарядов.

Так что «другу» рассказывать стоит не про пул, а про два принципа:
**снаряд в полёте — не объект, а строка в колонках**, и **картинка всех
снарядов — один MultiMesh, слоты которого раздаёт free-list**. Пул узлов —
это полумера, которая экономит `instantiate`, но оставляет по `_process`
на стрелу и по вызову отрисовки на спрайт.

⚠ **Зависимость ручек, нигде не охраняемая:** `BatchArrows` зовётся только
при `arrow_core` (`GameManager.gd:319`). Выключить `arrow_core` при
`projectile_core = true` — записи создаются, но не летят и не освобождают
слоты: стрелы застывают у лучника.
