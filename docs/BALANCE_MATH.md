# БАЛАНС: TTK, МОРАЛЬ, ЭКОНОМИКА, ВЕТЕРАНСТВО

Расчётный документ. Все числа отсюда **лежат в конфигах и правятся там**, а не
здесь: `scripts/unit_stats_config.gd` (характеристики, мораль, ветеранство,
экономика), `scripts/forge_config.gd` (древо кузницы). Этот файл объясняет,
**почему числа именно такие** и что сломается, если их двигать.

Проверяет всё описанное стенд **`qa_balance`** (20 проверок, headless):

    godot --headless --path . res://qa_balance/Test.tscn

Он не сверяет числа с копиями, а меряет СВОЙСТВА («дуэль линейной пехоты
длится дольше пятнадцати секунд», «первое исследование копится 2-4 минуты») —
поэтому правка баланса в конфиге доезжает до него сама.

## 1. Формула урона

```
    защита  = defense + armor + кузница + ветеранство + бонус стойки
    прошло  = урон × ARMOR_SOFTNESS / (ARMOR_SOFTNESS + защита)
    итог    = прошло × щит × бег
```

`ARMOR_SOFTNESS = 25` — «сколько очков защиты режут ровно половину урона».

### Почему не вычитание

Раньше было `урон − защита` с полом в 15 %. Два порока, оба видны в игре:

1. **Сверхлинейность.** У копейщика с уроном 14 первые три очка брони снимали
   21 % урона, следующие три — 27 % от остатка, а на восьми очках (броня 3 +
   стойка «оборона» +5) проходило 43 %. Ещё пара исследований — и фаланга
   становилась неубиваемой. Это и есть «терминаторы при перекачке».
2. **Зависимость от величины удара.** Одна и та же броня резала 60 % урона
   лучника и 25 % урона рыцаря. Балансировать такое нельзя: цена очка брони
   скачет от того, кто по тебе бьёт.

Долевая формула снимает оба: доля не зависит от удара, а каждое следующее очко
дешевеет само собой.

| защита | проходит урона | цена ЭТОГО очка |
|---:|---:|---:|
| 0 | 100.0 % | — |
| 1 | 96.2 % | 3.85 |
| 3 | 89.3 % | 3.3 |
| 5 | 83.3 % | 2.8 |
| 8 | 75.8 % | 2.2 |
| 12 | 67.6 % | 1.7 |
| 20 | 55.6 % | 1.26 |
| 30 | 45.5 % | 0.9 |

**Нуля не бывает никогда**, при любой сумме защиты: при 500 сквозь проходит
4.8 % урона. Бессмертие невозможно ПО ПОСТРОЕНИЮ, а не по страховочному порогу
(порог `MIN_DAMAGE_FRACTION` оставлен, но больше не срабатывает).

Отрицательная защита (пробитие брони, дебаффы) допустима и УСИЛИВАЕТ урон;
снизу она зажата `ARMOR_MIN_TOTAL = −12`, иначе формула делила бы на ноль.

| | Копейщик | Мечник/Рыцарь | Лучник |
|---|---:|---:|---:|

| Броня | 3 | 5 | 1 |
| Защита | 0 | 0 | 0 |
| Урон (обычный) | 14 | 20 | 18 |
| Урон (мощный, ротация 3+1) | 16¹ | 28 | 24¹ |

¹ ротацию `3×attack_1 + 1×attack_2` использует ТОЛЬКО мечник

про запас.

### Дуэль модель против модели (замер `qa_balance`, блок A)

| бьёт \ по кому | Копейщик | Мечник | Лучник |
|---|---:|---:|---:|
| Копейщик | **30.0 с** (15 ударов) | 36.0 с (18) | 18.0 с (9) |
| Мечник | **16.0 с** (10) | 17.6 с (11) | 9.6 с (6) |
| Лучник | 43.2 с (12) | 50.4 с (14) | 25.2 с (7) |

Было до правки: копейщик убивал копейщика за **9.3 с** (пять ударов). Стало
30 с и пятнадцать ударов — то есть удар перестал быть «пятой частью жизни» и
стал заметной, но не решающей единицей. Именно это и делает бой ритмичным:
игрок успевает увидеть размен, увести отряд, переключить стойку.

**Лучник в рукопашной складывается за 9.6 секунды, и это цена за двадцать
метров дальности.** Порог TTK на эту пару намеренно не распространяется:
задери его — и придётся задирать всей игре ради размена, которого в бою быть
не должно.

### Схватка двух отрядов 1 на 1 (замер `qa_balance`, блок B)

60 копейщиков против 60 копейщиков, обе стороны в атаке:

* **перелом (одна сторона потеряла половину состава) — 31 секунда;**
* полное истребление — 57 секунд.

Заказ был «30 … ±60 секунд», и мерить надо именно ПЕРЕЛОМ: после него бой
дорешивает паника, а не арифметика.

## 3. Мораль и паника («белый флаг»)

Мораль — **число отряда**, а не бойца: паникует и бежит отряд целиком.
Стартовое значение — средняя мораль состава.

| ручка | значение | что делает |
|---|---:|---|
| `MORALE_MAX` | 100 | потолок |
| `MORALE_LOSS_PER_DEATH` | 40 | ДОЛЯ штата × это число снимается за потери |
| `MORALE_LOSS_PER_HIT` | 0.02 | точит непрерывно, пока по отряду попадают |
| `MORALE_GAIN_PER_KILL` | 2.0 | за убитого врага |
| `MORALE_REGEN_PER_SEC` | 3.0 | восстановление ВНЕ боя |
| `PANIC_THRESHOLD` | 0.30 | абсолютный порог срыва |
| `PANIC_RATIO` | 0.5 | относительный: вдвое ниже противника |
| `PANIC_LAST_MEN` | 6 | третий порог: столько моделей осталось — срыв |
| `PANIC_LAST_MEN_MIN_ROSTER` | 12 | ниже этого штата третий порог не работает |
| `PANIC_STUN_SEC` | 20 | сколько длится потеря управления |
| `PANIC_FLEE_DIST` | 20 м | на сколько разбегаются |
| `PANIC_ARMOR_MULT` | 0.70 | −30 % защиты, пока паника |
| `PANIC_RECOVER_MORALE` | 0.55 | с какой моралью возвращается порядок |

### Порогов паники ТРИ, и все три обязательны

**Правка авг. 2026 по заказу владельца:** «паника от потерь должна срабатывать
не на 50 % отряда, а когда остаётся буквально три-семь моделек». Раньше порогов
было два и оба считали мораль; теперь добавлен третий, считающий ЖИВЫХ.

| порог | что ловит | как считается |
|---|---|---|
| **Абсолютный** | отряд, который перемололи | мораль ниже 30 % от максимума |
| **Относительный** | свежий отряд против ветеранов | мораль вдвое ниже, чем у того, с кем дерусь |
| **По счёту живых** | «нас почти не осталось» | осталось ≤ 6 моделей (при штате ≥ 12) |

**Третий порог НЕВЫРАЗИМ через мораль, и это не вопрос подбора числа.** Мораль
величина ДОЛЕВАЯ (доля потерь от штата), а требование АБСОЛЮТНОЕ («осталось
шестеро»): у отряда из шестидесяти это 90 % потерь, у отряда из двенадцати —
50 %. Через долю пришлось бы подбирать своё число каждому роду войск, то есть
завести таблицу там, где хватает одной константы.

**Малый отряд от него не срывается** (`PANIC_LAST_MEN_MIN_ROSTER`): огрызок из
пяти человек паниковал бы в тот же миг, как вступил в бой, не потеряв никого.

**Счёт ведётся В ПЕХОТИНЦАХ, а не в головах** (`squad_weight`, у кабанов 2.0 —
заказ владельца «1 всадник = 2 пехотинца»): конный отряд это десять моделей, и
без веса порог «осталось шестеро» срывал бы его после ЧЕТЫРЁХ потерь.

### Сколько потерь держит каждый род войск

Порог — 30 очков из 100. Потеря доли `d` состава снимает `40 × d`.

| род | мораль | ломается по морали | ломается по счёту (штат) |
|---|---:|---:|---:|
| Лучник | 45 | 37 % | 6 из 30 (80 %) |
| Гоблин | 55 | 62 % | 6 из 40 (85 %) |
| Копейщик | 65 | 87 % | 6 из 60 (90 %) |
| Мечник | 75 | не от потерь¹ | 6 из 30 (80 %) |
| Конница (кабаны) | 100 | не от потерь¹ | 3 из 10 (70 %) |

¹ Столбец считает ТОЛЬКО потери. Мораль точит ещё и `MORALE_LOSS_PER_HIT`
(0.02 за попадание по отряду) — за долгую свалку это набегает, поэтому
«не от потерь» означает «одними потерями порога не достать», а не
«паниковать не будет никогда».

**Число 40 подобрано так, чтобы мораль перестала быть главным путём к панике от
ПОТЕРЬ.** При прежних 90 копейщик срывался на 39 %, лучник на 17 % — то есть
отряд разбегался, будучи ещё вполне боеспособным, ровно то, на что жаловался
владелец. Теперь потери ловит третий порог, а мораль отвечает за то, за что
она и заведена: за «страшно» — непрерывное точение под обстрелом и
относительное сравнение с противником. Хрупкость родов войск при этом
сохранена: у лучника мораль всё ещё ниже всех, и относительный порог ломает
его первым.

### Что происходит при срыве

1. Над отрядом поднимается **белый флаг** (тот же узел и материал, что у знамени
   ветеранства, — своя реализация «картинки над отрядом» разъехалась бы с
   первой по высоте и правилам видимости).
2. Отряд бросает разметку строя и **разбегается врассыпную во все стороны** на
   20 м — направление у каждого своё, по золотому углу. Общий вектор «прочь от
   врага» был отменён владельцем: на экране он читался не как паника, а как
   организованный отход — шестьдесят человек ехали одной толпой в одну сторону.
   «Хаотично» при этом не значит `randf()`: два прогона одного боя обязаны
   давать одно поле, поэтому веер детерминирован (номер бойца + номер узла).
3. **Двадцать секунд отряд не принимает приказов** игрока, не атакует и не
   отвечает на удары; защита срезана на 30 %. Добить его в это время можно и
   нужно — в этом весь смысл: бой выигрывается сломом, а не полным
   истреблением.
4. По истечении срока порядок восстановлен, мораль — 55 от максимума. Не ноль
   (сорвался бы повторно в ту же секунду) и не максимум (выходил бы из
   разгрома свежим).

Замер `qa_balance`, блок C: 12 копейщиков против 36 мечников срываются с
моралью 18, убегают на 16 м, не исполняют приказ игрока, не держат ни одной
цели и через 20 секунд возвращаются в строй с моралью 56.

### Аура легенды

Отряд седьмого грейда (золотой штандарт) в радиусе 28 м даёт **своим ×1.5 к
порогу морали**, а **чужим НОВОБРАНЦАМ (грейд 0) ×0.75**. Аура привязана к
РАНГУ, а не к выбранному перку: любая легенда светит ею.

Множитель входит в ПОРОГ, а не в саму мораль — иначе уход легенды с поля резал
бы отряду накопленное число, и он паниковал бы от одного её отъезда.

## 5. Матрица ветеранства

Семь ступеней: три серебряные лычки, три синих флага, золотой штандарт.
Форма выбора — **3 / 4 / 5 — 3 / 4 / 5 — 5**. У каждого варианта **ровно три
ненулевых параметра: один главный и два вторичных**, и вторичные не всегда в
плюс — у брони это плата скоростью, у глухой обороны темпом удара. Именно она
делает выбор выбором.

Шаг главного параметра задан лестницей: **лычки +2, флаги +3, штандарт +4**.
Итог по одной ветке за всю жизнь отряда — **+13**, то есть ровно удвоение базы
(урон 14 → 27, броня 3 → 22). Удвоение — потолок намеренный: легендарный отряд
обязан стоить двух новобранцев, а не десяти.

конфига; три параметра у каждого перка оставлены намеренно, иначе панель
награды показывала бы пустую плашку.

| перк | ПРАВИЛО | параметры |
|---|---|---|
| **Непреклонные** | иммунитет к панике (плюс аура ранга) | +30 морали, +3 брони, +1 напора |
| **Пробитие брони** | игнорирует 30 % чужой защиты | +4 урона, −0.2 с перезарядки, +5 морали |
| **Стена щитов** | −40 % урона от стрел | +4 брони, +20 HP, −0.1 скорости |
| **Таран** | ×2 напор и упор в свалке | +2 напора, +20 HP, +3 урона |
| **Кровь за кровь** | +15 % запаса убийце за каждого убитого | +4 урона, +15 HP, +5 морали |

Любой отряд седьмого грейда, независимо от выбора, светит **аурой морали**
(см. раздел 3).

### Потолок прокачки

Копейщик, взявший всё в одну ветку, плюс полностью изученная кузница:

| | база | + кузница | + ветеранство | итог |
|---|---:|---:|---:|---:|
| Урон | 14 | +8.5 | +13 | **35.5** (×2.5) |
| Броня | 3 | +4 | +19 | **26** → снижение урона 49 % |
| HP | 180 | +48 | +90 | **318** (×1.8) |

Дуэль полностью прокачанного копейщика против такого же — 31 секунда; против
новобранца — тот бьёт его 78 секунд. **Легенда сильнее новобранца примерно в
два с половиной раза, а не в десять** — и это прямое следствие затухающей
брони: следующее очко после двадцатого стоит втрое дешевле первого.

## 6. Что сломается, если двигать числа

* **`ARMOR_SOFTNESS` вниз** — броня начнёт решать всё, и вернутся терминаторы.
  Вверх — её перестанут замечать, и вся ветка защиты в кузнице обесценится.
* **`MORALE_GAIN_PER_KILL` вверх** — паника перестанет случаться вовсе:
  пробовали 12, отряд отыгрывал мораль быстрее, чем терял людей.
* **Срок паники (`PANIC_STUN_SEC`) вниз** — исчезнет окно, ради которого
  механика и заведена: враг не успеет добить сломленных.
* **Шаг бонуса ветеранства вверх** — потолок ×2.5 поедет, и вернётся жалоба
  про терминаторов. Считать надо не «сколько даёт одна ступень», а **сумму по
  ветке за семь ступеней**.
* **Стартовый запас вверх** — вернётся «улучшения покупаются оптом за раз».
  Дилемма выбора держится РОВНО тем, что денег на два узла нет.

## 7. Структуры данных: где что лежит

**Отдельного файла-«баланса» намеренно нет.** Всё, что описано выше, уже стоит
в рабочих конфигах — иначе появился бы второй источник правды, и правка в одном
месте молча не доезжала бы до игры. Ниже — карта: какая структура за что
отвечает и как выглядит её строка.

### `scripts/unit_stats_config.gd` — характеристики, мораль, ветеранство

```gdscript
## Броня: ОДНА функция на весь проект. Бой, стенды и панель статов
## обязаны звать её, а не повторять арифметику
const ARMOR_SOFTNESS := 25.0          ## сколько защиты режет ровно половину урона
const ARMOR_MIN_TOTAL := -12.0        ## пол суммарной защиты (дебафы не дают ×∞)

static func damage_after_armor(amount: float, total_defense: float) -> float:
    var d: float = maxf(total_defense, ARMOR_MIN_TOTAL)
    if d == 0.0:
        return amount
    return amount * ARMOR_SOFTNESS / (ARMOR_SOFTNESS + d)

## Мораль отряда
const MORALE_MAX             := 100.0
const MORALE_LOSS_PER_DEATH  := 90.0   ## делится на ПОЛНЫЙ штат отряда
const MORALE_LOSS_PER_HIT    := 0.02
const MORALE_GAIN_PER_KILL   := 2.0
const MORALE_REGEN_PER_SEC   := 3.0

## Паника
const PANIC_THRESHOLD      := 0.30     ## абсолютный порог: доля от максимума
const PANIC_RATIO          := 0.5      ## относительный: вдвое ниже, чем у врага
const PANIC_STUN_SEC       := 20.0     ## столько отряд без управления
const PANIC_FLEE_DIST      := 20.0     ## на столько метров бежит
const PANIC_ARMOR_MULT     := 0.70     ## защита сломленного
const PANIC_RECOVER_MORALE := 0.55     ## с какой моралью возвращается в строй

## Легендарный (7-й) грейд
const LEGEND_TIER          := 7
const LEGEND_AURA_RADIUS   := 28.0
const LEGEND_AURA_ALLY_MULT := 1.50    ## порог паники соседям — легче
const LEGEND_AURA_FOE_MULT  := 0.75    ## врагам — тяжелее
const LEGEND_PIERCE_FRAC   := 0.30     ## «Пробитие брони»
const LEGEND_ARROW_GUARD   := 0.40     ## «Стена щитов»
const LEGEND_HEAL_FRAC     := 0.15     ## «Кровь за кровь»
const LEGEND_PUSH_MULT     := 2.0      ## «Таран»

## Строка рода войск. Ключи те же, что и раньше, — новых полей два:
## "morale" (стартовая мораль отряда) и уже бывшие боевые числа пересчитаны
STATS := {
    "spearman": {
        "health": 180.0, "armor": 3.0, "morale": 65.0,
        "attack_damage": 14.0, "attack_damage_2": 16.0, "attack_cooldown": 2.0,
        ...
    },
    ...
}
```

**Награда ветеранства — строка `_VET_BONUS_TEMPLATE[уровень][вариант]`.** Ровно
три ненулевых модификатора: один главный и два побочных. Легендарные помечены
`id` вида `legend_*` и лежат в том же списке `squads[sid]["chosen"]`, что и
обычные выборы, — сохранение партии подхватывает их само.

```gdscript
{
    "id": "legend_shieldwall",
    "name": "Стена щитов",
    "desc": "Строй смыкает щиты: −40 % урона от стрел",
    "bonus_defense": 3.0,      # главный
    "bonus_morale": 10.0,      # побочный
    "bonus_health": 12.0,      # побочный
}
```

### `scripts/forge_config.gd` — древо кузницы

Одна таблица `UNITS[род][ячейка]`; узел древа = слот улучшения, поэтому вся
машинерия исследований работает без ветвлений. Цена и время — по РЯДУ
(ряд 1 → тир I, ряды 2-3 → тир II, ряды 4-5 → тир III), бонус — по тиру.

```gdscript
"A1": {
    "name": "Наконечники I",
    "desc": "+1.5 к урону",
    "cost": {"wood": 300, "gold": 200, "stone": 0},
    "time": 25.0,
    "bonus_attack": 1.5,
},
```

### `GameManager` — мораль и паника во время партии

Мораль — **число ОТРЯДА**, а не бойца: живёт в `squads[sid]`, обходится раз в
`MORALE_SWEEP_SEC` (0.25 с), покадрового пути нет.

```gdscript
squads[sid] = {
    ...
    "morale": -1.0,          # −1 = «ещё не считали», ставится при первом обходе
    "full": 0,               # НАИБОЛЬШИЙ состав за жизнь отряда: делитель потерь
    "panic_until": 0,        # мс, до которых отряд без управления
    "panic_marker": null,    # узел белого флага над центром
}
```

Читатели: `squad_morale`, `squad_morale_frac`, `squad_panicked`,
`squad_full_size`, `squad_has_perk`, `squad_armor_pierce`. Писатели —
`squad_add_morale`, `credit_kill`, `squad_mark_hit`, `_sweep_morale`.

### `Unit` — исполнение на бойце

```gdscript
var _panicked: bool = false      # гейтит command_move / command_attack / авто-агро
func is_panicked() -> bool
func set_panicked(on: bool) -> void
func panic_flee(point: Vector3) -> void   # приказ ОТДАЁТСЯ ДО взвода признака
```

**Ничего из этого не заведено в C#.** Мораль считается по событиям (гибель,
удар, убийство) и обходом раз в четверть секунды — границу GDScript↔C# такое
пересекать не обязано, а `ArmyCore` держит только покадровые колонки.
