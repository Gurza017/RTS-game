# Паспорта юнитов — глубокий разбор (сводный реестр, 28.09.2026)

Точка входа к доказательной базе поюнитного аудита (план 28.09.2026: этапы
1-4 оптимизации ядра → тотальный аудит по родам войск). Собирается из трёх
источников и пополняется по мере прохождения этапов:

- **`UNITS_ANATOMY_DRAFT.md`** — анатомия тика по коду: диспетчер, «ведомые
  ядром», запросы за тик по состояниям (куда уходят: GDScript / C# / движок,
  как часто), таймеры, радиусы и хитбоксы по классам с `файл:строка`.
- **`UNITS_RETRO_DRAFT.md`** — ретроспектива прогонов и партий: мкс/тик и
  худшие тики по родам (Four d0/d1, full4k, VisAb), 30 аномалий с источником
  и статусом, срезы телеметрии трёх партий при FPS < 30, открытые вопросы.
- Этот файл — сводка, ход этапов и таблица «что уже подтверждено замером».

## 2. Ход этапов оптимизации ядра

### Этап 1 — визуальный тик армии в ядро (28.09.2026) — ЗАКРЫТ

Замер VisAb (A/B чередованием, потери заморожены, кадр логики):

| ручка | смысл | результат |
|---|---|---|
| `vis_quiet_sync` | утечка тишины: ядро снимало бит, поле GDScript оставалось | −0.44 мс (шум), строк в тике 338 → 305 |
| `vis_wake_lite` | удар / смена цели / смена ряда не метят позу базовым классам | 0.00 мс — удары не доминировали |
| `fling_core` | разлёт таймером ядра, догон без порога телепорта | **−0.68 мс, до −1.3 в плотной свалке**; «летит» 2600-4600 → 17-35 тиков/с |
| `vis_lod_quiet` | тишина вне LOD с отложенной позой | шум |
| `vis_dir_flip_clear` | копейщик снимает `_flip_dirty` в направленной позе | шум (исправление) |
| `look_core` | лента, замок удара, зеркало и переезд между бакетами — в ядре | **−2.1…−3.1 мс** (8.55/8.10/7.85 → 5.43/5.95/5.77), физтик без изменений |

Метод: счётчики причин пробуждений (`Unit._vis_wake(reason)`,
`ArmyCore.VisWakeWhy`) и отказов тишины по воротам — гипотезы проверялись
числом, а не догадкой (удар — отвергнут, разлёт и смена ленты — подтверждены).
