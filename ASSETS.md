# ASSETS — куда класть файлы

Единственный навигатор по ассетам. Заменил два расходившихся документа —
`README_ASSETS.md` (описывал раскладку `assets/sprites/…`, которой давно нет)
и `MAP_ASSETS.md`.

Движок адресует файлы **по имени**, каталоги не перечисляет никогда: в
экспортированной сборке исходных `.png` в пакете не существует вовсе, там лежат
`.ctex`, и `DirAccess` вернул бы пустой список. Подробности — в `CLAUDE.md`,
раздел «Exporting». Практическое следствие: **новую папку с ассетами надо
импортировать** (`godot --headless --import`), иначе `ResourceLoader.exists()`
ответит false, хотя файл на диске лежит. И **регистр имён важен даже на
Windows**: внутри `.pck` файловая система регистрозависимая.

## Фактическая раскладка

```
assets/
├── environment/                  ← общее для всех карт
│   ├── terrain/                  ← земля, деревья (Tree*.png), кусты (Bushe*.png), пеньки (Stump N.png)
│   ├── resources/                ← руда, камень, еда, вода (+ *_Highlight.png — ленты бликов)
│   ├── main menu/                ← фон и иконки главного меню
│   ├── menu ui/                  ← курсоры, полоски HP, рамки (внимание: папка со СТРОЧНОЙ «ui»)
│   └── Main Sounds/              ← общая музыка и эмбиенс
│
├── ui/
│   └── icons_units_human/        ← иконки юнитов в HUD
│
├── models/                       ← GLB. Из них используется только castle.glb
│
└── factions/
    ├── humans/                   ← единственная фракция с содержимым
    │   ├── icons/{buildings,hud,units}/   ← иконки построек, панели, войск
    │   ├── buildings/            ← спрайты зданий
    │   ├── Sounds Human/         ← голоса и боевые звуки людей
    │   └── units/
    │       ├── worker/  spearman/  archer/  soldier_pack/
    │       └── {Blue,Red,Purple,Yellow,Black} Units/   ← ленты по цвету стороны
    ├── orc/                      ← пусто, задел
    └── undead/                   ← пусто, задел
```

`assets/sprites/` и `assets/icons/` — **остатки старой раскладки**. `sprites/units`
и `sprites/resources` ещё держат запасные одиночные PNG (последняя ступень
цепочки запасных вариантов), `sprites/buildings` и `icons` пусты. Новые ассеты
туда класть не нужно.

## Звук: речь людей (реплики приказов)

Каталог речи — `assets/environment/Main Sounds/sound voice humans/` (константа
`AudioManager.DIR_VOICE`). Имена файлов — строчными через подчёркивание: PCK
регистрозависим, регистр сверяет стенд `qa_voice_ack` (блок A, все пути
движка через `AudioManager.all_asset_paths()`).

**СИНТЕЗИРОВАННЫЕ РЕПЛИКИ УДАЛЕНЫ (ТЗ 25.10.2026, блок 1).** Папки `orders/`
(«Forward!», «Attack!»…) и `worker/` («Yes, sir»…), собранные 24.10 синтезатором
речи Windows, звучали роботом и сняты вместе с событиями `order_move_short`,
`order_attack_short` и `worker_ack`-голосом: 1-4 отряда отвечают на приказ
штатным щелчком, рабочий — щелчками без голоса. Синтезированные голоса в
проект не класть; стенд `qa_voice_ack` A7 ловит любую `.wav` в этих папках.

Если владелец захочет живые голоса — кандидаты CC0 (OpenGameArt, автор
Scribe — «RTS commands and reports», «RTS commands 2»): один длинный mp3 со
всеми фразами подряд, нарезать по образцу `ORDER_REPLIES` с `from`/`to`.

Прочее в той же папке: `5+combat-voice-forward-march-543679.mp3` (фраза
массового марша), `combat-voice-hold-the-line-543680.mp3`, `horn_attacks.mp3`,
лупы шага и бега. Клич после рога (`war_cry`) — `Sounds Human/soldiers-battle-cry.wav`.

**Сняты из использования (файлы на диске остались):** `Sounds Human/angry1-4.wav`
(«Warrior Voice Pack», John Carroll) — рык на рыцаре, ТЗ 24.10.2026 «рычание
только гоблинам»; выкрик ярости рыцаря (`knight_angry`) теперь — клич людей и
выдохи усилия `VOXEfrt_ActionGrunt_*`.

## Ленты кадров

Лента — **горизонтальная полоска квадратных кадров** без полей:

```
[ кадр 1 ][ кадр 2 ] … [ кадр N ]     ширина = высота × N
```

- рабочий / лучник / мечник — кадр 192×192, копейщик — 320×320;
- PNG с прозрачностью;
- ноги персонажа стоят примерно в 57 px от низа кадра 192 px (и в 122 px от низа
  кадра 320 px) — именно на это рассчитан `Unit.SPRITE_BASE_Y`. Проверяется
  стендом `qa_ring`, раздел B: он читает альфа-канал ленты и говорит, на сколько
  сантиметров ноги разъехались с логической точкой бойца;
- `Tree*.png` и `Bushe*.png` — восьмикадровые ленты **качания на ветру**, их
  проигрывает шейдер (`shaders/veg_multimesh.gdshader`).

**Новый юнит обязан перечислять свои ленты по имени** (образец —
`Archer.SHEETS_COLOR` / `SHEETS_PLAIN`). Сканирование каталога
(`SpriteSheetParser.build_animated_sprite`) осталось только как запасной путь и
в сборке не работает.

## Цепочка запасных вариантов

Для каждого юнита и здания движок перебирает варианты по порядку и
останавливается на первом найденном:

```
1. лента кадров своей фракции   (assets/factions/<раса>/units/…)
2. общая лента                  (assets/factions/humans/units/<тип>/)
3. GLB-модель                   (assets/models/<тип>.glb)
4. одиночный PNG                (assets/sprites/units/…)
5. процедурная геометрия        (работает всегда, файлов не требует)
```

GLB-модели юнитов лежат в репозитории, но **намеренно не используются**: в
GL Compatibility их материалы рисуются чёрными. Из моделей в игре живёт только
замок.

## Иконки кузницы и ветеранства

Имена файлов в конфигах хранятся **без пути** (`"icon_sword.png"`), папка задана
одним местом — `unit_stats_config.SMITH_ICONS_DIR`. Разворачивает имя в полный
путь `smith_icon_path()`. Абсолютные `res://…` в конфиг не вписывают: переезд
папки тогда ломает всё молча.

## Проверка после переноса ассетов

`qa_build/Test.tscn` проходит по всей поверхности ассетов и собирает настоящие
ленты по каждому цвету стороны. Гонять его надо **дважды**: сначала headless,
потом — указав его как `run/main_scene`, в собранном **отладочном** экспорте.
Только второй прогон видит ошибки регистра и раскладки пакета.
