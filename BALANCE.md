# BALANCE — карта настроек

Где какое число лежит. Всё перечисленное правится **без единой строчки кода**:
конфиги — обычные словари GDScript, движок читает их вживую.

Общее правило: **числа живут в конфигах ровно по одному разу**. Если в двух
местах видно одно и то же значение — одно из них выведено из другого, и править
надо первоисточник. Стенды QA обязаны читать числа отсюда, а не хранить копии.

---

## 0. Единый шаблон модификаторов

`scripts/unit_stats_config.gd` → `MODIFIERS`

Один список всех модификаторов, какие в игре есть. **Каждый узел кузницы и
каждая награда за ветеранство несут этот набор целиком**: то, что запись не
даёт, стоит нулём. Чтобы добавить узлу дальность, не нужно вспоминать имя
ключа — строка уже стоит на месте, замените в ней 0 на число.

| ключ | что делает | где применяется |
|---|---|---|
| `bonus_attack` | + к урону удара | `Unit._upgrade_damage_bonus` |
| `bonus_armor` | + к броне | `Unit.take_damage` |
| `bonus_defense` | + к защите | `Unit.take_damage` |
| `bonus_health` | + к запасу HP, выдаётся и живым сразу | `GameManager._apply_health_bonus_now` |
| `bonus_speed` | + к скорости, м/с | `Unit._base_speed` |
| `bonus_range` | + к дальности атаки, м | `Unit._ready`, `_apply_range_bonus_now` |
| `bonus_cooldown` | **секунд долой** с перезарядки удара | `Unit._effective_cooldown`, пол `MIN_COOLDOWN` |
| `bonus_spread` | доля 0..1, на которую **кучнее** ложится стрельба | `Archer._on_attack_fired` |
| `bonus_push` | + к напору в свалке | `Unit._stand_power` |
| `bonus_morale` | + к морали | `Unit._stand_power` |
| `bonus_carry` | + к грузу рабочего за ходку | `Worker.carry_capacity` |
| `bonus_gather` | **секунд долой** из цикла добычи | `Worker._cycle_time`, пол `MIN_CYCLE_TIME` |

**Знак везде один: плюс — это хорошо.** Там, где по смыслу надо уменьшить
(перезарядка, разброс, цикл добычи), вычитание делает код. Колонка с обратным
знаком в балансной таблице — гарантированная ошибка при правке.

## 1. Базовые характеристики юнитов

`scripts/unit_stats_config.gd` → `STATS`

Ключи верхнего уровня: `warrior`, `spearman`, `archer`, `worker`, `monk`.

| поле | смысл |
|---|---|
| `health` | запас HP |
| `movement_speed` | скорость, м/с |
| `attack_1` / `attack_2` | урон обычного и усиленного удара (у мечника ротация 3+1) |
| `attack_range` | дальность, м (ближний бой 1.4–2.5, лучник 20) |
| `attack_cooldown` | секунд между ударами |
| `defense`, `armor` | два слагаемых защиты |
| `morale`, `push_force` | мораль и напор в свалке |
| `push_every` | раз во сколько ударов срабатывает толчок (по умолчанию `Unit.PUSH_EVERY` = 1, то есть на каждый) |
| `charge_push_mult` | множитель смещения при толчке; применяется **после** потолка |
| `name_genitive_plural` | родительный падеж мн. ч. для названия по рангу («Отряд ветеранов КОПЕЙЩИКОВ») |
| `gather_time`, `gather_amount` | только у рабочего: цикл добычи и груз за ходку |
| `attack_range_cap` | **жёсткий потолок** дальности с учётом всех прибавок кузницы (нет ключа — потолка нет) |
| `arrow_speed`, `arrow_arc` | только у лучника: скорость и навес стрелы |

Только у ударной конницы (нет ключа `charge_range` = «этот род войск не конница»):

| поле | смысл |
|---|---|
| `charge_range` | за сколько метров до цели начинается разгон |
| `charge_min_runup` | сколько метров надо **реально проехать** в разгоне, чтобы удар засчитался (без этого таран срабатывал бы и в плотном бою) |
| `charge_speed_mult` | во сколько раз конница ускоряется на разгоне |
| `charge_impact_frac` | доля **максимального** запаса ЖЕРТВЫ, снимаемая ударом с разгона |
| `charge_splash` | радиус первого ряда контакта, м |
| `charge_knockback` | на сколько метров разлетаются накрытые |
| `charge_counter_frac` | доля **своего** запаса, теряемая при лобовом навале на копья |

Рядом в том же файле:

- `STANCES` — стойки «Атака» / «Защита»: множители скорости атаки, морали,
  напора, прибавка к защите и `holds_ground` (в «Защите» отряд **не сходит с
  места вообще** — ни за отступающим врагом, ни по прямому приказу);
- `SQUAD_SIZE_*` — размер отряда по роду войск, `SQUAD_SIZE_HARD_CAP` — потолок;
- `TRAINING` — цена, время найма и число колонок в строю, по зданиям;
- `BUILDINGS` — цена и время постройки зданий;
- `PLAYER_STARTING_RESOURCES` / `AI_STARTING_RESOURCES` — стартовый банк.
  Значения намеренно одинаковые; два блока существуют, чтобы фору можно было
  дать **осознанно**;
- `GARRISON_*` — вместимость замка, скорость лечения, срок восстановления
  модели, радиус входа, авто-выход;
- `HOUSE_FOOD_INCOME` / `HOUSE_FOOD_INTERVAL` — еда с домов;
- `VISION_MULT` / `VISION_MIN` / `BUILDING_VISION` — обзор в тумане войны.

## 2. Ветеранство (знамёна на копьях)

`scripts/unit_stats_config.gd`

- `VET_CONFIG` — по типу войск: `thresholds` (сколько убийств на каждый из семи
  уровней) и `bonuses`. Четыре независимых блока, правка одного не задевает
  остальные.
- `_VET_BONUS_TEMPLATE` — сами награды: семь уровней по пять вариантов. Каждый
  вариант — `id`, `name`, `icon` и **полный шаблон модификаторов** (см. §0).
  Награда вправе давать сразу несколько прибавок: обе строки уже есть, поставьте
  числа. Короткой пары `stat`/`value` в таблице нет — она выводится из
  модификаторов при чтении, чтобы одно число не описывалось дважды.
- `VET_BANNER_TIERS` — как выглядит знамя на каждом из семи уровней:
  `rank` (звание в родительном падеже), `shape` (вымпел / «ласточкин хвост» /
  штандарт), `cloth` (цвет полотнища), `chevrons` + `chevron_dir` (лычки и куда
  они смотрят), `white_tip` (белый наконечник). **Один источник правды** и для
  картинки над отрядом, и для значка ранга в панели, и для названия отряда.
- `BANNER_CHEVRON`, `BANNER_TIP_COLOR`, `BANNER_GOLD` — цвета лычек,
  наконечника и золота. Вынесены из таблицы намеренно: они одни на все грейды,
  и разноцветные лычки превратили бы шкалу званий в набор непохожих значков.
- Пропорции самой картинки (длина вымпела, глубина «ласточкина хвоста», толщина
  лычек, герб) — `scripts/BannerArt.gd`; мировой размер и высота над землёй —
  `scripts/SquadBanner.gd` (подбираются глазом на оконном стенде `qa_banner`).
  **Увеличивать знамя надо в `BannerArt` (`FLAG_H`/`FLAG_LEN`/`STD_*`), а не
  подъёмом `PIXEL_SIZE`:** тот тянет и древко, и пика превращается в мачту.
- `VET_STAR_TIERS`, `VET_TIER_COLORS`, `VET_TIER_SCALE` — **наследие**: прежняя
  звёздная шкала. Игрой не читается, держится только стендами прежнего вида.

Пороги **могут повторяться** (`[40, 40, 40, …]` — одно убийство даёт несколько
уровней), и уровень отряда никогда не понижается.

### Стойки отряда

`scripts/unit_stats_config.gd` → `STANCES`

- `lock_position` — **позиция залочена наглухо** (сейчас `false`): ни приказ на движение, ни
  приказ атаки не сдвигают бойца, разрешён только разворот и удар по вошедшему
  в дальность. У обороны `true` (заказ владельца). Единственное исключение —
  смыкание рядов отряда. Поставьте `false`, чтобы вернуть прежнее поведение,
  когда фаланга шла в точку приказа.
- Прочие поля (`push_mult`, `push_resist`, `attack_speed_mult`,
  `move_speed_mult`, `morale_mult`, `defense_bonus`, `holds_ground`) описаны в
  шапке самой таблицы.

## 3. Кузница: древо исследований

`scripts/forge_config.gd` → `UNITS`

Пять вкладок (`UNIT_TABS`): `worker`, `warrior`, `spearman`, `archer`, `monk`.
Внутри вкладки — сетка 5 рядов × 4 колонки, ячейки `1a`…`5d`.

Поля ячейки:

| поле | смысл |
|---|---|
| `icon` | имя файла из `SMITH_ICONS_DIR` (только имя, без пути!) |
| `prereq` | ячейки, которые надо изучить прежде. Условие **И** |
| `link` | ячейки, соединённые горизонтальной стрелкой. **АЛЬТЕРНАТИВНЫЙ** путь (ИЛИ), не требование |
| `name`, `desc` | подпись и строка эффекта |
| `cost_gold` / `cost_wood` / `cost_stone` | цена, списывается при заказе |
| `research_time` | секунд в кузнице |
| `squad_unlock_cost` | **именно это поле делает узел способностью**: сколько золота платит каждый отряд, чтобы её получить |
| `toggle` | `true` — способность работает как режим вкл/выкл (например «Залповый огонь») |
| `bonus_*` | полный шаблон модификаторов (см. §0) |

Правила доступа: колонку **D открывает весь свой ряд** (`1a + 1b + 1c` для `1d`),
а не стрелка. Вертикальные связи — настоящие зависимости, горизонтальные — только
разрешают шаг вбок.

Форма графа теперь **у каждой вкладки своя** — общей таблицы `GRID` больше нет.
Цена этого известна: чтобы поменять само древо (а не одну ячейку), правку надо
повторить в каждой боевой вкладке.

Старые плоские слоты `unit_stats_config.UPGRADE_SLOTS` живы для совместимости.
**Не адресуйтесь к `UPGRADE_SLOTS[0]`**: у него стоит заглушка `requires`, из-за
которой он не откроется никогда.

## 4. Искусственный интеллект

`scripts/ai_start_army_limit.gd` — весь ИИ настраивается отсюда.

| группа | ключи |
|---|---|
| Армия | `SQUAD_LIMIT` (по родам войск), `WORKER_LIMIT`, `START_WORKERS` |
| Темп | `PEACE_SECONDS` (мирная фаза), `THINK_INTERVAL` (такт решений), `MAX_QUEUED_ORDERS` |
| Оборона | `DEFENSIVE_MODE`, `MAP_CONTROL_FRACTION`, `DEFENSE_LINE_WIDTH`, `DEFENSE_ENGAGE_RADIUS`, `HOME_GUARD_PER_TYPE` |
| Патрули | `PATROL_SQUADS`, `PATROL_RADIUS`, `PATROL_DWELL` |
| Озеро | `SEND_SURPLUS_TO_LAKE`, `USE_LAKE_AS_RALLY`, `LAKE_CONTEST_RADIUS`, `PUSH_BASE_AFTER_LAKE_WIN` |
| Тактика волн | `TACTICS`, `TACTICS_IN_ORDER`, `FLANK_SPREAD` |
| Обход мечниками | `AI_WARRIOR_FLANK`, `FLANK_ARC_RADIUS`, `FLANK_TRIGGER_DIST`, `FLANK_REACH` |
| Отход лучников | `AI_ARCHER_KITE`, `KITE_TRIGGER_DIST`, `KITE_BACK_DIST` |
| Отвод разбитых | `AI_SQUAD_RETREAT`, `RETREAT_STRENGTH`, `RETREAT_THREAT_RADIUS` |
| Фаланга | `PHALANX_RANKS`, `AI_SPEAR_PHALANX_ON_MARCH`, `CONTACT_RADIUS` |
| Кузница | `AI_RESEARCH_FORGE`, `AI_FORGE_WEIGHTS`, `AI_FORGE_EXTRA_BRANCHES`, `AI_RESEARCH_GOLD_RESERVE` |
| Способности | `AI_BUY_SQUAD_ABILITIES`, `AI_ABILITY_GOLD_RESERVE` |
| Ветеранство | `AI_AUTO_VETERAN`, `AI_VETERAN_PREFERENCE` |
| Прочее | `AI_COUNTER_ATTACK`, `REBUILD_BARRACKS_FREE`, `ARMY_LOST_THRESHOLD` |

`RETREAT_STRENGTH` считается от **собственного пика отряда**, а не от размера в
конфиге: отряды ИИ собираются подкреплениями, и по конфигу свежее пополнение
читалось бы как разбитое.

## 5. Экономика рабочих и ресурсы на карте

### Сколько и как быстро

- `unit_stats_config.STATS.worker.gather_time` — секунд на цикл добычи
- `unit_stats_config.STATS.worker.gather_amount` — сколько уносит за ходку
- `Worker.WOOD_SPEEDUP` — множитель цикла для дерева
- `Worker.MIN_CYCLE_TIME` — пол цикла: ниже не опустят никакие исследования
- `Worker.CHOP_SWING_RATE` / `MINE_SWING_RATE` — темп замахов топором и киркой
  (это **и звук, и тряска** — они не могут разъехаться)
- `unit_stats_config.DEFAULT_CLUSTER_GOLD` / `_STONE` — **запас одной кучи руды**.
  Это единственное число, задающее объём месторождения: композиция кучи на него
  не влияет никак

### Что стоит на карте

`scripts/Main.gd`:

| константа | смысл |
|---|---|
| `MAP_HALF_X` / `MAP_HALF_Z` | размер карты |
| `GOLD_CLUSTERS` / `STONE_CLUSTERS` | сколько куч руды и камня |
| `CLUSTER_LAYOUTS` | три рукописных композиции кучи (кто где лежит) |
| `PIECE_CLASSES` | классы кусков: масштаб и целевая высота |
| `LAYOUT_SPAN_STONE` / `LAYOUT_SPAN_GOLD` | во сколько сжать композицию |
| `LAKE_ENABLED`, `LAKE_CENTER`, `LAKE_RADIUS` | озеро (сейчас **выключено**) |
| `_add_forest_clusters` → `target_clusters` | сколько рощ на карте |
| `CORNER_AREA_MULT` / `CORNER_DENSITY_MULT` | насколько гуще углы карты |
| `POCKET_INNER` / `POCKET_OUTER` / `POCKET_OPEN_DEG` / `POCKET_TREES` | подкова леса вокруг базы |

Размер самих кусков руды — в `scripts/ResourceNode.gd`: `PIECE_TARGET_H` (целевая
высота, единственная ручка «вся руда крупнее/мельче»), `ZOOM_MIN` / `ZOOM_MAX`
(насколько сильно кусок разрешено тянуть от родного размера пикселей),
`ORE_OBSTACLE_MIN_SCALE` (с какого размера кусок становится препятствием).

### Ловушки

- `PIECE_CLASSES` больше **не задаёт запас** руды: раньше объём месторождения
  выводился из его внешнего вида, и правка композиции молча меняла баланс.
- Куча руды — **один объект** (`MineCluster`) с общим запасом. Рабочие занимают
  места по внешнему обводу и внутрь не заходят.
- Мелкие и средние куски руды **не препятствия** (`ORE_OBSTACLE_MIN_SCALE`):
  шестнадцать полуметровых колец вплотную были лабиринтом.

## Как проверить, что правка доехала

Стенды в папках `qa_*` запускаются так:

```
<godot> --headless --path . res://qa_<имя>/Test.tscn
```

Слово провала в отчётах — **«НЕ ПРОШЛО»** (не «FAIL»), итог — строка
«провалов: N из M».

| правил | гоняйте |
|---|---|
| `STATS`, стойки | `qa_hold`, `qa_spear`, `qa_guard`, `qa_melee` |
| `VET_CONFIG` | `qa_vet` |
| `forge_config.UNITS` | `qa_forge`, `qa_upgrade`, `qa_cfg` |
| настройки ИИ | `qa_ai`, `qa_ai2` |
| экономику и ресурсы | `qa_res2`, `qa_mine`, `qa_tree`, `qa_stump` |
| что угодно из перечисленного | плюс `qa_mass_perf --count=3000` на скорость |
